## Confirmed Mu4 gaps

- [#232: valid WebSocket payload corruption](https://github.com/3redronin/mu-server/issues/232). A 65,536-byte binary echo and a 125-byte ping sent in small TCP writes return changed bytes. These are valid payloads within the configured limits; differences are not just framing.
- [#233: reserved opcode handling](https://github.com/3redronin/mu-server/issues/233). The server does not consistently perform protocol-error termination for reserved data/control opcodes.
- [#234: invalid close codes and UTF-8 reasons](https://github.com/3redronin/mu-server/issues/234). An invalid close code reaches internal-error handling (1011), while malformed UTF-8 in a reason is replacement-decoded and answered with a normal close (1000).

Fresh Java 21 fixtures replay cases `1.2.7,2.6,4.1.1,7.5.1,7.9.1`: all five fail on Mu4 and pass on Mu3. The standalone PR package repeats those same results. These representative issues do not claim to assign every one of the 31 failures to a fully proven root cause; a post-fix full replay remains necessary.

Mu4's five review results are `6.4.1`, `6.4.2` (non-strict invalid-text detection timing) and `7.1.6`, `7.13.1`, `7.13.2` (informational close behavior). They remain visible for case-specific assessment, not automatically bugs or accepted passes.

Mu3 is a reference, not a conformance oracle. Its WebSocket failures are mostly around text/UTF-8 and close behavior. The legacy echo adapter uses the public fragment callbacks, while Mu4 uses SimpleWebSocket message assembly; differences require assessment before attributing them specifically to Netty. The reference's failures do not excuse candidate failures.

## Limits and reproduction

The profile deliberately excludes Autobahn `9.*` (large-message/performance) and `12.*`/`13.*` (compression extensions), runs `ws://` rather than WSS, and raises fixture WebSocket frame/message limits to 16 MiB where supported. Server-default limits, WSS, compression, capacity/backpressure and long soak are separate work. h2spec covers its older RFC7540/7541 suite; additional RFC9113 coverage and certificate verification remain necessary.
